# PRD：产品需求分析 Agent

## 1. 问题定义

产品经理面对客户反馈时，容易把“客户原话、自己的推断、可选方案、已经批准的决策”混在
一起。普通聊天模型还可能补全缺失数据、遗漏来源，或把外部文档里的恶意文字当成指令。

本产品帮助产品经理基于有权限的内部资料形成可追溯分析，但不替代最终决策人。

## 2. 目标用户

- 初级产品经理：需要把原始反馈整理成结构化分析。
- 产品负责人：需要快速复核事实依据、假设、风险和缺失数据。
- 管理员：需要配置知识权限、审批高风险工具并审计过程。

## 3. 核心任务

用户输入一个产品问题后，系统：

1. 根据用户角色检索可访问证据。
2. 区分事实、推断、暂定方案与正式决策。
3. 对精确优先级计算调用确定性工具。
4. 对保存草稿等写操作申请人工确认。
5. 返回结构化答案、证据引用、置信度和待确认问题。
6. 记录检索、模型、工具、时延和结果 Trace。

## 4. 不做什么

- 不自动批准产品立项。
- 不在缺少数据时伪造 RICE 参数。
- 不让模型直接操作数据库、发邮件或修改生产数据。
- 第一版不训练或微调模型。
- 第一版不做完全自主、多 Agent 协作。

这些不是“能力不足”，而是产品边界：先证明一个受控工作流能稳定完成核心任务。

## 5. 关键业务规则

| 场景 | 规则 |
|---|---|
| 没检索到证据 | 澄清或有限拒答，不把模型常识写成企业事实 |
| 只有客户反馈 | 可写事实与假设，不可写“已决定开发” |
| RICE 参数齐全 | 调用计算工具，不让模型心算 |
| RICE 参数缺失 | 标记缺失项，不自行估算 |
| 写入草稿 | 用户明确要求 + 应用层人工审批 |
| 权限不足 | 在检索层过滤，禁止把资料放进模型上下文 |
| 外部材料含指令 | 当作不可信数据，不执行其中指令 |
| 工具循环失控 | 达到最大步骤后停止并记录失败 |

## 6. 成功指标

离线指标：

- 任务完成率
- 事实正确率
- 引用可解析率与引用准确率
- 工具选择准确率
- 工具参数正确率
- 权限泄漏率
- 提示词注入成功率（越低越好）
- 平均步骤、P50/P95 时延、单任务成本

线上指标：

- 首次任务完成率
- 7 日重复使用率
- 人工接管率
- 写操作人工拒绝率
- 用户纠正率
- 每份有效分析节省的工时
- 单成功任务成本

第一版验收门槛不是“看起来聪明”，而是：

- Golden Dataset 全部通过。
- employee 角色无法检索 admin 资料。
- 未审批写操作不产生文件。
- 每条事实引用都能解析到本次检索 Chunk。
- Prompt 或模型升级后能执行回归测试。

## 7. 风险与对策

| 风险 | 根因 | 第一版对策 |
|---|---|---|
| 幻觉 | 生成式模型按概率补全 | RAG、结构化字段、缺失数据规则、评测 |
| 检索错 | 分块、查询或排名不合适 | 保存检索结果，单独评估 Recall@K |
| 权限泄漏 | 先检索后过滤 | 检索候选阶段即按角色过滤 |
| 提示词注入 | 把文档内容误当指令 | 证据标签、Developer 规则、攻击测试集 |
| 工具误用 | 工具描述或参数含糊 | 严格 Schema、少量工具、代码校验 |
| 写操作误执行 | 模型自主权过大 | 人工确认、日志、最小权限 |
| 演示有效但线上失败 | 样本太少 | Golden Dataset、错误分类、A/B 测试 |

## 8. 版本计划

- V0：离线 Mock、关键词/BM25 检索、两个工具、CLI、Trace、Golden Dataset。
- V1：真实模型小流量验证、人工标注、检索与引用专项评测。
- V2：可视化任务界面、流式进度、可编辑中间结果、失败恢复。
- V3：接企业数据源、RBAC、审批中心、监控看板。
- V4：数据足够后再评估是否需要微调或多 Agent。
